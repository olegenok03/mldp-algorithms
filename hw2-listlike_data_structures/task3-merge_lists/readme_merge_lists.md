# Вариант 1. Использование фиктивного узла

## Описание решения

В первом варианте решения используется фиктивный (dummy) узел: это позволяет не реализовывать отдельную логику для инициализации головы результирующего списка и не обработывать краевые случаи, когда один из списков изначально пуст.

Мы создаем фиктивный узел `dummy`, и заводим указатель `cur_node`, который будет перемещаться по мере добавления новых узлов, всегда указывая на последний элемент формируемого списка:

```python
cur_node = dummy = ListNode(0, None)
```

Далее, пока не будет достигнут конец хотя бы одного из списков (`node1` или `node2`), сравниваются значения текущих узлов. `cur_node.next` инициализируется узлом с меньшим значением, после чего указатель `cur_node` и указатель выбранного списка сдвигаются на один шаг вперед:

```python
while node1 and node2:
    if node1.val < node2.val:
        cur_node.next = node1
        cur_node = cur_node.next
        node1 = node1.next
    else:
        cur_node.next = node2
        cur_node = cur_node.next
        node2 = node2.next
```

Поскольку длины списков могут различаться, один из них закончится раньше. Оставшаяся часть второго (непустого) списка гарантированно больше всех уже добавленных элементов и уже отсортирована. Мы можем присоединить всю оставшуюся часть за одну операцию (`node1 or node2` вернет тот указатель, который не равен `None`):

```python
cur_node.next = node1 or node2
```

Головой готового списка будет являться узел, следующий за фиктивным. В конце мы освобождаем память от фиктивного узла и возвращаем голову:

```python
new_head = dummy.next
del dummy
return new_head
```

**Оценка временной сложности алгоритма:** $O(n + m)$, где $n$ и $m$ — длины списков `list1` и `list2` соответственно. В худшем случае цикл выполнится $n + m - 1$ раз.
**Оценка сложности алгоритма по памяти:** $O(1)$. Алгоритм переиспользует существующие узлы, изменяя их указатели `next`, и не требует выделения объема памяти, пропорционального размеру списков (кроме $O(1)$ для фиктивного узла и нескольких указателей).

# Вариант 2. Без использования фиктивного узла

## Описание решения

Во втором варианте мы избегаем создания фиктивного узла. Из-за этого требуется явно обработать краевые случаи (когда хотя бы один из списков изначально пуст), а также вручную определить, какой из узлов станет новой головой `new_head`.

Сначала обрабатываем пустые списки. Если один из них пуст, возвращаем другой:
```python
if not node1:
    return node2
if not node2:
    return node1
```

Датем сравниваем головы обоих непустых списков, чтобы определить точку старта, инициализировать указатель текущего элемента `cur_node` и сдвинуть соответствующий указатель на следующий элемент:
```python
if node1.val < node2.val:
    cur_node = new_head = node1
    node1 = cur_node.next
else:
    cur_node = new_head = node2
    node2 = cur_node.next
```

После определения головы алгоритм работает точно так же, как и в первом варианте (итерирация по узлам, их сравнение и переназначение ссылок):

```python
while node1 and node2:
    if node1.val < node2.val:
        cur_node.next = node1
        # ... сдвиги ...
```

По выходу из цикла, как и ранее, к получившемуся списку присоединяется оставшаяся часть непустого списка. Функция возвращает инициализированный ранее указатель `new_head`.

**Оценка временной сложности алгоритма:** $O(n + m)$. 
**Оценка сложности алгоритма по памяти:** $O(1)$. 
Характеристики сложности полностью идентичны первому варианту.
