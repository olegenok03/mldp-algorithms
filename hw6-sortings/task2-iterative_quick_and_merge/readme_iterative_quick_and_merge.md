# Задание 2. Итеративные Quick Sort и Merge Sort

## Постановка задачи

В рамках задания требуется реализовать нерекурсивные (итеративные) версии двух классических алгоритмов сортировки:
1. **Merge Sort (сортировка слиянием)** — без использования рекурсии.
2. **Quick Sort (быстрая сортировка)** — без использования системного стека вызовов функций.

---

## Архитектура решения

Переход от рекурсивного подхода к итеративному раскрывает ключевые различия между двумя алгоритмами:

### 1. Итеративный Merge Sort (Канонический Bottom-Up подход)
В рекурсивной версии мы двигались **сверху вниз (Top-Down)**: рекурсивно делили массив пополам до единичных элементов, после чего на обратном ходе выполняли слияния.

В итеративной версии наиболее эффективным и каноническим является подход **снизу вверх (Bottom-Up)**:
* **Без использования стека:** не требует эмуляции стека вызовов, весь процесс управляется двумя простыми циклами.
* **Инкремент ширины блока (`width`):**
  1. На первом проходе сливаются смежные отрезки длины $1$ в отрезки длины $2$ (`width = 1`).
  2. На втором проходе сливаются отрезки длины $2$ в отрезки длины $4$ (`width = 2`).
  3. Процесс продолжается (`width *= 2`), пока ширина подмассива меньше длины массива $N$.
* **Оптимизированное слияние (`_merge`):**
  * В буфер `aux` копируется **только левая половина** `[lo : mid + 1]`.
  * Правая половина читается напрямую из `arr_copy`.
  * Цикл `while i <= mid and j <= hi` производит сравнение `arr_copy[j] < aux[i]`.
  * Оставшийся левый хвост переносится срезом `arr_copy[k : hi + 1] = aux[i : mid + 1]`. Правый хвост уже стоит на своих местах.
* **Пропуск слияния уже упорядоченных блоков:** проверка `if arr_copy[mid] > arr_copy[mid + 1]:` вызывает слияние только тогда, когда стык блоков неупорядочен.

### 2. Итеративный Quick Sort (Эмуляция стека в куче)
В отличие от Merge Sort, в Quick Sort ключевая операция (разбиение Ломуто и выбор pivot) происходит на прямом спуске:
* **Явный стек (`stack = []`):** пары границ `(lo, hi)` текущих подмассивов хранятся в обычном списке Python.
* **Разбиение Ломуто на замкнутых отрезках `[lo, hi]`:**
  * Опорный элемент: `pivot = arr_copy[hi]`.
  * Цикл `for j in range(lo, hi)` сдвигает элементы $\le \text{pivot}$ в левую часть.
  * `pivot` занимает свою финальную позицию `i + 1`.
* **Добавление подзадач в стек:**
  * В стек помещаются границы левой части `(lo, i - 1)` и правой части `(i + 1, hi)`.
  * Базовый случай `if hi <= lo: continue` отсекает отрезки длины $\le 1$.
* **Преодоление ограничения рекурсии Python:**
  * Рекурсивный Quick Sort при худшем разбиении падал с ошибкой `RecursionError` при $N \ge 1000$ (лимит системного стека фреймов Python).
  * Итеративная версия хранит стек в динамической памяти (heap-allocated list), что позволяет без ошибок и переполнений сортировать массивы любого размера при любых наихудших распределениях данных.

## Код решения

```python
def merge_sort_iterative(arr: list) -> list:
    """
    Канонический итеративный Bottom-Up Merge Sort:
    - обходится без стека (два цикла while/for);
    - буфер aux выделяется ровно 1 раз;
    - копирование только левой половины в aux;
    - проверка упорядоченности смежных блоков.
    """
    if len(arr) <= 1:
        return arr.copy()

    arr_copy = arr.copy()
    aux = [0] * len(arr_copy)

    def _merge(lo: int, mid: int, hi: int) -> None:
        aux[lo : mid + 1] = arr_copy[lo : mid + 1]

        i, j, k = lo, mid + 1, lo

        while i <= mid and j <= hi:
            if arr_copy[j] < aux[i]:
                arr_copy[k] = arr_copy[j]
                j += 1
            else:
                arr_copy[k] = aux[i]
                i += 1
            k += 1

        if i <= mid:
            arr_copy[k : hi + 1] = aux[i : mid + 1]

    width = 1
    n = len(arr_copy)
    while width < n:
        for lo in range(0, n - width, width * 2):
            mid = lo + width - 1
            hi = min(lo + 2 * width - 1, n - 1)
            if arr_copy[mid] > arr_copy[mid + 1]:
                _merge(lo, mid, hi)
        width *= 2

    return arr_copy


def quick_sort_iterative(arr: list) -> list:
    """
    Итеративный Quick Sort с явным стеком подмассивов (lo, hi)
    и схемой разбиения Ломуто на замкнутых отрезках [lo, hi].
    """
    arr_copy = arr.copy()
    stack = [(0, len(arr) - 1)]

    while stack:
        lo, hi = stack.pop()

        if hi <= lo:
            continue

        pivot = arr_copy[hi]
        i = lo - 1
        for j in range(lo, hi):
            if arr_copy[j] <= pivot:
                i += 1
                arr_copy[i], arr_copy[j] = arr_copy[j], arr_copy[i]

        i += 1
        arr_copy[i], arr_copy[hi] = arr_copy[hi], arr_copy[i]

        stack.append((lo, i - 1))
        stack.append((i + 1, hi))

    return arr_copy
```

## Оценка сложности

### 1. Merge Sort (итеративный)
* **Временная сложность (Time Complexity):**
  * Внешний цикл `while width < n` выполняет ровно $\lceil \log_2 N \rceil$ итераций.
  * Внутренний цикл `for` на каждом уровне просматривает суммарно $N$ элементов.
  * **Худший, средний и лучший случай:** $O(N \log N)$ (на уже упорядоченных массивах проверка `arr_copy[mid] > arr_copy[mid + 1]` сокращает время за счет пропуска `_merge`).
* **Пространственная сложность (Space Complexity):**
  * Буфер `aux`: ровно $N$ элементов ($O(N)$).
  * Копия входного массива: $O(N)$.
  * Память под переменные циклов: $O(1)$ (стек не используется).
  * **Итого:** строго $O(N)$ дополнительной памяти.

### 2. Quick Sort (итеративный)
* **Временная сложность (Time Complexity):**
  * **Лучший и средний случай:** $O(N \log N)$ (сбалансированное разбиение).
  * **Худший случай:** $O(N^2)$ (для схемы Ломуто с крайним pivot — на отсортированных/обратных массивах).
* **Пространственная сложность (Space Complexity):**
  * Стек `stack`: $O(\log N)$ пар в среднем случае, до $O(N)$ в худшем случае.
  * Копия массива: $O(N)$.
  * **Итого:** $O(N)$ дополнительной памяти (в динамической памяти, без ограничений стека ОС).
