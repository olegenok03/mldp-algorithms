# Задание 1. Рекурсивные Quick Sort и Merge Sort

## Постановка задачи

В рамках задания требуется:
1. Реализовать рекурсивную версию **Merge Sort (сортировка слиянием)**.
2. Реализовать рекурсивную версию **Quick Sort (быстрая сортировка)**.
3. Реализовать декоратор `@benchmark`, замеряющий время выполнения функции с помощью монотонных часов высокой точности.
4. Придумать и реализовать наборы тестов, на которых время выполнения `Merge Sort` и `Quick Sort` **существенно отличается**, и объяснить причины наблюдаемой разницы.

---

## Архитектура решения

Решение объединяет три ключевых компонента:

### 1. Декоратор для замера времени (`@benchmark`)
* **Точность измерений:** использует `time.perf_counter()`, обеспечивающий наивысшее доступное системное разрешение и гарантированную монотонность (отсутствие влияния корректировок системного времени).
* **Сохранение метаданных:** с помощью `@wraps(func)` сохраняет сигнатуру, имя (`__name__`) и документацию (`__doc__`) исходной функции.
* **Формат результата:** возвращает кортеж `(result, elapsed_time)`, где `result` — результат вызова функции, а `elapsed_time` — время выполнения в секундах. Это позволяет легко валидировать корректность сортировки одновременно с замером времени.

### 2. Рекурсивный Merge Sort (Top-Down с оптимизированным буфером O(N))
Реализация опирается на классический Top-Down подход с рядом ключевых оптимизаций:
* **Защита от мутации:** создается рабочая копия входного массива (`arr_copy = arr.copy()`), что сохраняет иммутабельность исходных данных.
* **Единый буфер аллокации:** вспомогательный массив `aux = [0] * len(arr_copy)` выделяется **ровно один раз** в самом начале, предотвращая накладные расходы на постоянные мелкие аллокации.
* **Оптимизация копирования (вдвое меньше записей):** строка `aux[lo : mid + 1] = arr_copy[lo : mid + 1]` копирует в буфер **только левую половину**. Правая половина остаётся в `arr_copy` и читается напрямую.
* **Упрощённый цикл сравнения и ранний выход:** цикл `while i <= mid and j <= hi` содержит **всего одно сравнение** `arr_copy[j] < aux[i]`, исключая лишние проверки границ на каждой итерации.
* **Обработка хвостов срезом:** 
  * Если раньше исчерпалась правая половина (`j > hi`), оставшийся левый хвост дописывается быстрым срезом CPython: `arr_copy[k : hi + 1] = aux[i : mid + 1]`.
  * Если раньше исчерпалась левая половина (`i > mid`), правые элементы **уже находятся на своих финальных позициях** в `arr_copy` — их вообще не нужно перемещать!
* **Устойчивость (Stability):** строгое неравенство `arr_copy[j] < aux[i]` при равенстве ключей направляет поток в ветку `else`, отдавая приоритет левому элементу `aux[i]`.
* **Оптимизация на упорядоченных данных:** проверка `if arr_copy[mid] <= arr_copy[mid + 1]: return` полностью исключает вызов `_merge`, если стык половин уже упорядочен (время $O(N)$ на отсортированных данных).

### 3. Рекурсивный Quick Sort (Схема разбиения Ломуто на замкнутых отрезках [lo, hi])
* **Работа на копии:** также работает с локальной копией `arr_copy`.
* **Разбиение Ломуто (Lomuto Partition Scheme):** работает на замкнутых отрезках `[lo, hi]` (обе границы включительно, согласовано с `_merge_sort_rec_inplace`):
  * Базовый случай: `if hi <= lo: return` (отрезок длины $\le 1$ уже отсортирован).
  * В качестве опорного элемента (`pivot`) выбирается правый край отрезка: `arr_copy[hi]`.
  * Указатель `i = lo - 1` отслеживает границу элементов, меньших либо равных `pivot`.
  * Цикл `for j in range(lo, hi)` за один проход перемещает элементы $\le \text{pivot}$ влево.
  * По завершении цикла `pivot` обменивается с элементом на позиции `i + 1`, вставая на своё финальное отсортированное место.
* Рекурсивные вызовы `_quick_sort_rec_inplace(lo, i - 1)` и `_quick_sort_rec_inplace(i + 1, hi)` сортируют левый и правый отрезки, исключая уже зафиксированный `pivot` на позиции `i`.

## Код решения

```python
import time
from functools import wraps


def benchmark(func):
    """Декоратор для точного замера времени выполнения функции."""
    @wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        res = func(*args, **kwargs)
        elapsed = time.perf_counter() - start
        return res, elapsed

    return wrapper


def merge_sort_recursive(arr: list) -> list:
    """
    Оптимизированный Top-Down Merge Sort:
    - буфер aux O(N) выделяется ровно один раз;
    - в aux копируется только левая половина (в 2 раза меньше записей);
    - цикл слияния с единственным сравнением arr_copy[j] < aux[i];
    - проверка упорядоченности смежных половин.
    """
    if len(arr) <= 1:
        return arr.copy()

    arr_copy = arr.copy()
    aux = [0] * len(arr_copy)

    def _merge(lo: int, mid: int, hi: int) -> None:
        aux[lo : mid + 1] = arr_copy[lo : mid + 1]

        i, j, k = lo, mid + 1, lo

        while i <= mid and j <= hi:
            if arr_copy[j] < aux[i]:
                arr_copy[k] = arr_copy[j]
                j += 1
            else:
                arr_copy[k] = aux[i]
                i += 1
            k += 1

        if i <= mid:
            arr_copy[k : hi + 1] = aux[i : mid + 1]

    def _merge_sort_rec_inplace(lo: int, hi: int) -> None:
        if hi <= lo:
            return

        mid = lo + (hi - lo) // 2

        _merge_sort_rec_inplace(lo, mid)
        _merge_sort_rec_inplace(mid + 1, hi)

        if arr_copy[mid] <= arr_copy[mid + 1]:
            return

        _merge(lo, mid, hi)

    _merge_sort_rec_inplace(0, len(arr_copy) - 1)
    return arr_copy


def quick_sort_recursive(arr: list) -> list:
    """
    Рекурсивный Quick Sort на замкнутых отрезках [lo, hi]
    со схемой разбиения Ломуто.
    """
    arr_copy = arr.copy()

    def _quick_sort_rec_inplace(lo: int, hi: int) -> None:
        if hi <= lo:
            return

        pivot = arr_copy[hi]
        i = lo - 1
        for j in range(lo, hi):
            if arr_copy[j] <= pivot:
                i += 1
                arr_copy[i], arr_copy[j] = arr_copy[j], arr_copy[i]

        i += 1
        arr_copy[i], arr_copy[hi] = arr_copy[hi], arr_copy[i]

        _quick_sort_rec_inplace(lo, i - 1)
        _quick_sort_rec_inplace(i + 1, hi)

    _quick_sort_rec_inplace(0, len(arr_copy) - 1)
    return arr_copy
```

## Оценка сложности

### 1. Merge Sort
* **Временная сложность (Time Complexity):**
  * **Худший случай ($O(N \log N)$):** массив делится строго пополам на каждом шаге (высота дерева $\log_2 N$), на каждом уровне суммарно выполняется слияние $N$ элементов.
  * **Средний случай ($O(N \log N)$):** гарантированно логарифмическое число уровней слияния.
  * **Лучший случай ($O(N)$):** на уже отсортированном массиве проверка `arr_copy[mid] <= arr_copy[mid + 1]` отсекает все вызовы `_merge`, выполняя лишь линейный проход по дереву.
* **Пространственная сложность (Space Complexity):**
  * Буфер `aux`: выделяется ровно один массив размера $N$ ($O(N)$).
  * Копия входного массива: $O(N)$.
  * Стек вызовов: $O(\log N)$ уровней рекурсии.
  * **Итого:** $O(N)$ дополнительной памяти.

### 2. Quick Sort
* **Временная сложность (Time Complexity):**
  * **Лучший случай ($O(N \log N)$):** каждый раз выбранный pivot делит массив ровно пополам.
  * **Средний случай ($O(N \log N)$):** для случайных перестановок вероятность сбалансированного разбиения близка к единице.
  * **Худший случай ($O(N^2)$):** возникает при несбалансированном разбиении (одна часть пустая, вторая длины $K - 1$). Для схемы Ломуто с крайним pivot это происходит на **уже отсортированных**, **обратно отсортированных** массивах, а также на массивах из **одинаковых элементов**.
* **Пространственная сложность (Space Complexity):**
  * Стек вызовов: $O(\log N)$ в лучшем/среднем случае, но **$O(N)$ в худшем случае**.
  * Копия массива: $O(N)$.
  * **Итого:** $O(N)$ дополнительной памяти.
