# Задание 3. K-th Maximum (Quickselect)

## Постановка задачи

Требуется найти **$k$-й по величине (наибольший)** элемент массива.

**Ограничения задачи:**
1. Нельзя просто отсортировать массив (требуется асимптотика лучше $O(N \log N)$).
2. Запрещено использовать структуру данных «куча» (Heap / Priority Queue).
3. **Подсказка:** алгоритм **Quickselect** (быстрый выбор).

**Примеры из условия:**
* Ввод: `nums = [3, 2, 1, 5, 6, 4], k = 2` $\to$ Вывод: `5` (1-й наибольший — 6, 2-й — 5).
* Ввод: `nums = [3, 2, 3, 1, 2, 4, 5, 5, 6], k = 4` $\to$ Вывод: `4` (в порядке убывания `[6, 5, 5, 4, 3, 3, 2, 2, 1]`, 4-й элемент — 4).

> **Замечание о трактовке условия («максимум vs минимум»):**  
> В теоретическом Computer Science порядковая статистика ($k$-th order statistic) традиционно отсчитывается от минимума ($1$-я — минимум, $N$-я — максимум). Однако формулировка задачи воспроизводит **LeetCode 215: Kth Largest Element in an Array**, а имя каталога `task3-kth_maximum` и контрольные примеры подтверждают, что под «$k$-м по величине» подразумевается именно **$k$-й максимум**.

## Архитектура решения

Алгоритм **Quickselect** (разработанный Тони Хоаром) основан на идее разбиения из Quick Sort, но обладает ключевым отличием:

1. **Односторонний спуск (без рекурсии и стека):**
   * В Quick Sort после разбиения необходимо сортировать **обе** половины массива ($T(N) = 2T(N/2) + O(N) = O(N \log N)$).
   * В Quickselect точное финальное положение опорного элемента (`pivot`) на индексе `i` сразу определяет, в какой половине находится целевой индекс `target_idx = k - 1`.
   * Вторая половина массива **отбрасывается навсегда**.
   * Уравнение сложности: $T(N) = T(N/2) + O(N)$. По сумме геометрической прогрессии $N + N/2 + N/4 + \dots = 2N = O(N)$ алгоритм находит ответ в среднем за **линейное время $O(N)$**.

2. **Разбиение Ломуто по невозрастанию (`arr_copy[j] >= pivot`):**
   * Смена знака сравнения на `>=` собирает все элементы, большие либо равные pivot, в левой части отрезка.
   * После установки pivot на позицию `i` гарантируется:
     * слева от `i` лежат элементы $\ge \text{pivot}$;
     * справа от `i` лежат элементы $\le \text{pivot}$.
   * Таким образом, $k$-й по величине элемент соответствует индексу `target_idx = k - 1`.

3. **Рандомизация опорного элемента (`Randomized Quickselect`):**
   * Детерминированный выбор крайнего элемента (`pivot = arr_copy[hi]`) на отсортированных данных приводит к худшему времени $O(N^2)$.
   * Выбор `pivot_idx = random.randint(lo, hi)` с обменом `arr_copy[pivot_idx] <-> arr_copy[hi]` перед разбиением математически гарантирует ожидаемое время $O(N)$ на любых входных данных.

4. **Инвариант диапазона и выход из цикла:**
   * На протяжении всей работы поддерживается инвариант:
     $$lo \le target\_idx \le hi$$
   * Условие `while lo < hi` продолжается до тех пор, пока в рабочем отрезке есть хотя бы 2 элемента.
   * Если pivot встал точно на `target_idx`, результат возвращается немедленно.
   * Если отрезок сузился до одного элемента ($lo = hi$), то в силу инварианта $lo = hi = target\_idx$, и строка `return arr_copy[target_idx]` возвращает искомый элемент без единой лишней операции.

## Код решения

```python
import random


def kth_maximum(arr: list, k: int) -> int:
    """
    Поиск k-го максимума алгоритмом Quickselect:
    - O(N) математическое ожидание времени;
    - O(1) памяти на состояние (без стека и рекурсии);
    - случайный выбор pivot исключает худший случай O(N^2);
    - не мутирует исходный массив arr.
    """
    arr_copy = arr.copy()
    target_idx = k - 1
    lo, hi = 0, len(arr) - 1

    while lo < hi:
        pivot_idx = random.randint(lo, hi)
        arr_copy[pivot_idx], arr_copy[hi] = arr_copy[hi], arr_copy[pivot_idx]
        pivot = arr_copy[hi]

        i = lo - 1
        for j in range(lo, hi):
            if arr_copy[j] >= pivot:
                i += 1
                arr_copy[i], arr_copy[j] = arr_copy[j], arr_copy[i]

        i += 1
        arr_copy[i], arr_copy[hi] = arr_copy[hi], arr_copy[i]

        if i == target_idx:
            return arr_copy[i]
        elif i > target_idx:
            hi = i - 1
        else:
            lo = i + 1

    return arr_copy[target_idx]
```

## Оценка сложности

### Временная сложность (Time Complexity)
* **Средний случай (Average Case):** $O(N)$  
  Благодаря случайному выбору pivot размер подмассива на каждом шаге в среднем уменьшается вдвое:
  $$T(N) \le N + \frac{N}{2} + \frac{N}{4} + \dots + 1 = O(N)$$
* **Лучший случай (Best Case):** $O(N)$  
  Первый же случайно выбранный pivot сразу встал на позицию `target_idx` за один проход по массиву длины $N$.
* **Худший случай (Worst Case):** $O(N^2)$  
  Теоретически возможен, если генератор случайных чисел каждый раз будет выбирать минимальный или максимальный элемент. Вероятность этого сценария стремится к нулю ($\approx (1/N!)$).

### Пространственная сложность (Space Complexity)
* **Вспомогательная память (Auxiliary Space):** $O(1)$  
  Алгоритм итеративен: не использует рекурсивных фреймов и не создаёт структур данных вроде `stack`.
* **С учётом копии входных данных:** $O(N)$  
  Создаётся одна копия `arr_copy = arr.copy()` для соблюдения принципа неизменяемости (immutability) входного списка.
