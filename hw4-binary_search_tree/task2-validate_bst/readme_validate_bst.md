# Задача 2. Validate BST

## Описание решения

В задаче требуется проверить, является ли произвольное бинарное дерево корректным бинарным деревом поиска (BST). 

Инвариант BST гласит: для каждого узла с ключом $K$:
- Все ключи в его левом поддереве должны быть строго меньше $K$.
- Все ключи в его правом поддереве должны быть строго больше $K$.

### Выбор подхода: почему обход внутри функции эффективнее построения списка

Существуют два основных способа решения через симметричный (in-order) порядок:

1. **Построить in-order список и проверить его отсортированность:**
   - Пройти всё дерево, собрать ключи в `list[int]`, затем проверить, что `res == sorted(set(res))`.
   - *Недостатки:* всегда расходует $O(N)$ дополнительной памяти под массив всех ключей и всегда выполняет полный обход дерева за $O(N)$, даже если первое же нарушение находится в самом левом листе.

2. **Итеративный in-order обход внутри функции «на лету» (Выбранное решение):**
   - Мы обходим дерево итеративно с помощью стека `tree_stack` и указателя `curr`.
   - Храним только один скаляр — ключ предыдущего посещённого узла `prev_key`.
   - В момент снятия очередного узла со стека проверяем: если `prev_key is not None and curr.key <= prev_key`, мы **немедленно прерываем обход** и возвращаем `False` (**ранний выход / early exit**).
   - *Преимущества:* не выделяется дополнительный массив на $N$ элементов (память $O(H)$ вместо $O(N)$), а в случае ошибки алгоритм завершается досрочно, не тратя время на оставшуюся часть дерева.

---

### Код решения

```python
def validate_bst(tree: BinarySearchTree) -> bool:
    curr = tree.root
    tree_stack: list[TreeNode] = []
    prev_key: int | None = None

    while curr is not None or tree_stack:
        if curr is not None:
            tree_stack.append(curr)
            curr = curr.left
        else:
            curr = tree_stack.pop()
            # В корректном BST ключи в порядке in-order строго возрастают
            if prev_key is not None and curr.key <= prev_key:
                return False
            prev_key = curr.key
            curr = curr.right

    return True
```

---

### Оценка сложности

- **Временная сложность:**
  - В худшем случае (корректное дерево или нарушение в самом конце): $O(N)$, где $N$ — число узлов в дереве.
  - В лучшем / среднем случае при наличии ошибок: $O(K)$, где $K \ll N$ — число узлов до первого нарушения инварианта.
- **Пространственная сложность:** $O(H)$, где $H$ — высота дерева ($O(\log N)$ в сбалансированном дереве, $O(N)$ в вырожденном). Память расходуется только на стек обхода, без создания списка всех элементов.

## Визуализация решения

### Пример 1. Корректное дерево (Valid BST)

Рассмотрим дерево:

```text
         4
       /   \
      2     6
     / \   /
    1   3 5
```

Ожидаемый in-order порядок: `1 < 2 < 3 < 4 < 5 < 6`.

#### Пошаговая трассировка для корректного дерева

| Шаг | `curr` | `tree_stack` (ключи) | `prev_key` | Проверка `curr.key <= prev_key` | Действие |
|:---:|:------:|:--------------------:|:----------:|:-------------------------------:|---|
| 1   | `Node(4)` | `[]`            | `None`     | —                               | Push 4 в стек, `curr = 4.left` |
| 2   | `Node(2)` | `[4]`           | `None`     | —                               | Push 2 в стек, `curr = 2.left` |
| 3   | `Node(1)` | `[4, 2]`        | `None`     | —                               | Push 1 в стек, `curr = 1.left` |
| 4   | `None`    | `[4, 2, 1]`     | `None`     | `prev_key is None`              | `pop()` ➔ 1. `prev_key = 1`. `curr = 1.right` (`None`) |
| 5   | `None`    | `[4, 2]`        | `1`        | $2 \le 1$ ➔ `False`             | `pop()` ➔ 2. `prev_key = 2`. `curr = 2.right` (`Node(3)`) |
| 6   | `Node(3)` | `[4]`           | `2`        | —                               | Push 3 в стек, `curr = 3.left` |
| 7   | `None`    | `[4, 3]`        | `2`        | $3 \le 2$ ➔ `False`             | `pop()` ➔ 3. `prev_key = 3`. `curr = 3.right` (`None`) |
| 8   | `None`    | `[4]`           | `3`        | $4 \le 3$ ➔ `False`             | `pop()` ➔ 4. `prev_key = 4`. `curr = 4.right` (`Node(6)`) |
| 9   | `Node(6)` | `[]`            | `4`        | —                               | Push 6 в стек, `curr = 6.left` |
| 10  | `Node(5)` | `[6]`           | `4`        | —                               | Push 5 в стек, `curr = 5.left` |
| 11  | `None`    | `[6, 5]`        | `4`        | $5 \le 4$ ➔ `False`             | `pop()` ➔ 5. `prev_key = 5`. `curr = 5.right` (`None`) |
| 12  | `None`    | `[6]`           | `5`        | $6 \le 5$ ➔ `False`             | `pop()` ➔ 6. `prev_key = 6`. `curr = 6.right` (`None`) |
| 13  | `None`    | `[]`            | `6`        | —                               | Стек пуст. Завершение цикла. **Возврат `True`** |

### Пример 2. Некорректное дерево с ранним выходом (Invalid BST)

Рассмотрим классическую ошибку структуры: локально для узла 15 левый потомок 6 корректен ($6 < 15$), но глобально узел 6 лежит в правом поддереве корня 10, нарушая инвариант ($6 < 10$):

```text
         10
        /  \
       5    15
           /  \
          6    20
```

#### Пошаговая трассировка с досрочным завершением

| Шаг | `curr` | `tree_stack` (ключи) | `prev_key` | Проверка `curr.key <= prev_key` | Действие |
|:---:|:------:|:--------------------:|:----------:|:-------------------------------:|---|
| 1   | `Node(10)`| `[]`             | `None`     | —                               | Push 10 в стек, `curr = 10.left` |
| 2   | `Node(5)` | `[10]`           | `None`     | —                               | Push 5 в стек, `curr = 5.left` |
| 3   | `None`    | `[10, 5]`        | `None`     | `prev_key is None`              | `pop()` ➔ 5. `prev_key = 5`. `curr = 5.right` (`None`) |
| 4   | `None`    | `[10]`           | `5`        | $10 \le 5$ ➔ `False`            | `pop()` ➔ 10. `prev_key = 10`. `curr = 10.right` (`Node(15)`) |
| 5   | `Node(15)`| `[]`             | `10`       | —                               | Push 15 в стек, `curr = 15.left` |
| 6   | `Node(6)` | `[15]`           | `10`       | —                               | Push 6 в стек, `curr = 6.left` |
| 7   | `None`    | `[15, 6]`        | `10`       | **$6 \le 10$ ➔ `True`**         | **Нарушение порядка! Немедленный возврат `False`** |

> **Обратите внимание:** Алгоритм завершил работу на шаге 7. Узлы `15` и `20` даже не потребовалось извлекать или обходить.
